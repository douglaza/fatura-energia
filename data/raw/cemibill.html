O Cemig Bill automatiza a leitura de faturas CEMIG: obtém ou recebe o PDF, extrai dados, grava no PostgreSQL e permite consultar o histórico por API, Excel e assistente local.

02 / Evolução

Quatro etapas, cada uma resolvendo um problema.

Os tutoriais anteriores registram o estado do projeto em momentos diferentes; esta linha do tempo resume os recursos que permaneceram na versão atual.

V1 · BASE

API, parser e banco

CRUD de faturas e consumos, upload de PDF, validações HTTP, relacionamento em cascata e migrations Alembic. O schema de leitura passou a declarar os consumos para que apareçam na resposta da API.

V2

Automação e pipeline

Playwright navega no portal CEMIG; o login e o reCAPTCHA permanecem manuais. O comando `python -m app.downloader --persistir` conecta download, parser e PostgreSQL.

V3

Dashboard Excel

OpenPyXL gera Resumo Executivo, Histórico, Faturas e Gráficos. O consumo é consolidado por mês; a projeção é a média móvel dos até três meses mais recentes, sem modelar sazonalidade.

V3.1

Assistente com LLM local

O adapter usa o SDK OpenAI contra a API compatível do Ollama. Consultas numéricas conhecidas continuam em SQL; explicações, recomendações e perguntas abertas usam Qwen local.

03 / Problemas resolvidos

Correções que melhoraram a confiança nos dados.

Os valores do dashboard dependem da qualidade da extração e da forma correta de agregar as leituras.

ProblemaSolução
Consumos não apareciam no detalhe da faturaIncluir o relacionamento no schema de resposta da API.
PDFs CEMIG variam de layoutParser reconhece mês e vencimento em colunas e separa nome do cliente do endereço da distribuidora.
Uma fatura soma vários meses de históricoDashboard consolida uma leitura por mês, em vez de somar o histórico como se fosse o mês atual.
Gráficos sem série mensalO workbook usa a série mensal consolidada para alimentar linhas, colunas e variação percentual.
Upload dava erro 500 em PDF fora do padrão esperadoUma rota única valida os campos e a API responde com erro explícito quando falta informação.
Download falhava em clone sem pasta de destinoO downloader cria o destino antes de salvar e usa `data/raw/fatura.pdf`; PDFs continuam ignorados pelo Git.
04 / Preparar ambiente

Banco, Ollama e API.

Execute na raiz do repositório. O modelo usa armazenamento e recursos da máquina local; o projeto não baixa o modelo automaticamente.

1. Preparar projeto e banco

Crie o ambiente, instale os requisitos, configure `.env` e aplique as migrations.

python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
docker compose up -d
alembic upgrade head

2. Instalar Ollama e modelo

No Linux, instale o serviço e baixe o modelo gratuito localmente.

curl -fsSL https://ollama.com/install.sh | sh
ollama pull llama3.2:3b
ollama run llama3.2:3b "Explique uma fatura de energia"

3. Conferir configuração do modelo

O `.env.example` contém os padrões. A chave `ollama` é apenas necessária para o SDK; não é uma credencial de conta.

OLLAMA_BASE_URL=http://localhost:11434/v1
OLLAMA_API_KEY=ollama
OLLAMA_MODEL=llama3.2:3b
OLLAMA_TIMEOUT_SECONDS=90

4. Iniciar API e explorar

Com o Ollama ativo, inicie o FastAPI e consulte o Swagger.

uvicorn app.main:app --reload
# http://localhost:8000/docs
05 / V3.1

Use o assistente nas faturas existentes.

As rotas precisam de API, banco e faturas cadastradas. Consultas numéricas conhecidas continuam funcionando sem Ollama; chamadas de linguagem natural dependem do modelo e retornam 503 se ele estiver parado.

GET

Explicar fatura

/ai/faturas/2026-10/explicar retorna consumo, comparação com o mês anterior quando disponível e valor total em JSON na chave `explicacao`.

POST

Chat

/ai/chat recebe `{"pergunta":"Qual foi meu maior consumo?"}`. Maior consumo, conta mais cara, consumo anual e gasto médio usam SQL; perguntas abertas usam Ollama. A resposta vem em `resposta`.

POST

Consultor energético

/ai/consultor produz sugestões gerais baseadas em histórico, média e meses recentes; resposta na chave `recomendacao`.

06 / Limites e privacidade

Dados locais; respostas verificáveis.

A aplicação mantém SQL como fonte dos números e envia ao Ollama apenas um contexto agregado para a linguagem natural.

Contexto limitado

Até 36 meses de referência, consumo e valores de fatura.

Sem identificadores

Nome, instalação e texto integral do PDF não são incluídos nos prompts.

Sem tarifa inventada

Componentes tarifários não estruturados no banco não são inferidos como fatos.

Respostas geradas por LLM podem conter erros. Confira valores importantes no dashboard ou na fatura original.
